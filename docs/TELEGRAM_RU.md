# Telegram-кабинет «Пар'ИМБА'нк»

Бот предоставляет личный кабинет в обычном чате: общий с сайтом баланс, билеты, каталог розыгрышей, получение билетов с подтверждением, результаты, запросы бесплатных монет и просмотр уведомлений. Это не Telegram Mini App. Административные команды, поддержка в виде переписки с командой и автоматическая передача призов в боте не реализованы; для них используется сайт.

**Текущее состояние:** подготовлен бесплатный вариант Cloudflare Workers Free с webhook и сохранён альтернативный Node.js runner. Реальный токен BotFather не предоставлен; вход в Cloudflare, публикация Worker и работа кабинета не подтверждены. Создание имени бота, сборка кода и проверка Sites/R2 не заменяют проверку настоящего Telegram. Начните с [инструкции Workers Free](../bot/CLOUDFLARE_RU.md).

## 1. Как устроено подключение

Сайт остаётся в прежней аудитории Sites. В основном бесплатном варианте отдельный Cloudflare Worker принимает защищённый webhook Telegram и обращается к `/api/telegram/bridge`. Альтернативный Node.js-процесс получает обновления сам через long polling (`getUpdates`). Telegram не отправляет произвольные webhook-запросы прямо в закрытый сайт. Открывать сайт всем ради интеграции не требуется.

У транспорта два независимых доступа к сайту: сервисный токен Sites и отдельный `TELEGRAM_BRIDGE_SECRET`. Токен Telegram находится только в серверной конфигурации Worker или runner. Пользователь доказывает доступ к своему аккаунту обычным входом на сайт, затем подтверждает связь с числовым Telegram ID. Данные и списания остаются в общей D1; второго баланса в Telegram нет.

## 2. Создание бота через BotFather

1. Откройте официальный [@BotFather](https://t.me/BotFather). Проверьте именно этот адрес.
2. Отправьте `/newbot` и следуйте его диалогу: задайте отображаемое имя, затем свободный username. Username состоит из латинских букв, цифр и подчёркиваний, имеет длину 5–32 символа и заканчивается на `bot`.
3. Сохраните выданный токен в менеджере секретов или защищённой конфигурации сервера. Не отправляйте его в переписку, не вставляйте в GitHub, исходники, скриншоты или публичные команды терминала.
4. Запишите username без `@`: он понадобится серверной настройке сайта. Токен и username — разные значения.
5. При раскрытии токена отзовите его через BotFather и обновите секрет процесса. Не продолжайте использовать раскрытый токен.

Официальные инструкции Telegram: [создание и управление ботом](https://core.telegram.org/bots/features#botfather) и [получение токена](https://core.telegram.org/bots/tutorial#obtain-your-bot-token). Для Worker меню устанавливает операторский CLI настройки webhook, для long polling — runner при старте. Отдельно придумывать команды в BotFather не нужно.

## 3. Подготовка сайта

Сначала примените актуальные миграции и опубликуйте версию с `/telegram`, `/api/telegram/link` и `/api/telegram/bridge`. Для локальной схемы используйте порядок из [INSTALL_RU.md](INSTALL_RU.md); локальная миграция не меняет опубликованную D1.

В серверной конфигурации сайта задайте:

| Значение | Назначение |
| --- | --- |
| `TELEGRAM_BOT_USERNAME` | Username выбранного бота без `@`, для ссылок пользователя |
| `TELEGRAM_BRIDGE_SECRET` | Случайный секрет 32–256 символов без переводов строк; одинаковый на сайте и в процессе бота |

Получите поддерживаемый платформой сервисный доступ именно к этому сайту. Интеграция Sites возвращает его в поле `siwc_bypass_bearer_token` ответа `get_site`; это не Git-токен доступа к исходникам. Он предназначен серверу бота, а не браузеру пользователя. Права на выпуск и хранение токена инфраструктуры не появляются при назначении административной роли в приложении. Если оператор не располагает таким сервисным доступом, подключение ещё не готово.

Не используйте токен BotFather как секрет bridge и не заменяйте сервисный доступ заголовками с самостоятельно указанным пользователем. В штатном runner запрос проходит оба уровня: `OAI-Sites-Authorization: Bearer ...` для платформы и `Authorization: Bearer ...` для bridge. Ни один из этих секретов не передаётся в URL, ссылке привязки или сообщении Telegram.

## 4. Настройки транспорта

Для Workers используйте runtime secrets по [CLOUDFLARE_RU.md](../bot/CLOUDFLARE_RU.md). Образец для Node.js long polling находится в [bot/env.example](../bot/env.example). Реальные значения храните в секретных переменных хоста либо отдельном закрытом файле вне репозитория.

| Переменная | Обязательность | Содержимое |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Да | Токен от BotFather |
| `SITE_URL` | Да | Только HTTPS-origin сайта, например `https://your-site.example`, без пути, параметров, логина и пароля |
| `SITES_SERVICE_TOKEN` | Да | Сервисный доступ к выбранному сайту Sites |
| `TELEGRAM_BRIDGE_SECRET` | Да | Тот же секрет 32–256 символов, что в серверной конфигурации сайта |
| `BOT_ENABLED` | Задайте явно | `false` при подготовке, `true` после настройки; Worker без этого ключа выключен |
| `TELEGRAM_BOT_USERNAME` | Да для Worker | Ожидаемый username бота, соответствующий токену и настройке сайта |
| `TELEGRAM_WEBHOOK_SECRET` | Только Worker | Отдельный секрет из 32–256 URL-safe символов для входящих запросов Telegram |
| `BOT_STATE_FILE` | Только long polling | Файл прогресса обработки, например `/var/lib/parimbank-bot/offset.json`; по умолчанию `./bot/.state/offset.json` относительно рабочей папки |

`TELEGRAM_BOT_USERNAME` нужен сайту и транспорту для проверки ожидаемого бота через `getMe`. Worker требует это значение; в Node runner его также следует задавать. В Node runner отсутствие `BOT_ENABLED` сохраняет прежний автоматический запуск, поэтому в новой конфигурации всегда задавайте `false` до подготовки. У Worker отсутствие ключа означает `false`.

Эквивалентные прямые команды — `node bot/runner.mjs` и `node bot/test-bot.mjs`.

Только Node runner использует файл состояния с offset обновлений, без баланса или текстов переписки. Worker этого файла не требует. Его каталог должен находиться на постоянном диске и быть доступен для записи только процессу и ответственному оператору. Локальные секреты, checkpoint и lock-файлы нельзя отправлять в репозиторий.

## 5. Размещение

### Основной вариант: Workers Free

Следуйте [CLOUDFLARE_RU.md](../bot/CLOUDFLARE_RU.md): отдельный Worker из папки `bot/`, runtime secrets, проверка ожидаемого username и защищённая регистрация webhook. Постоянный сервер и offset-диск не нужны. Бесплатный тариф имеет квоты запросов и CPU; публикация ещё не выполнена. Публичного setup-адреса, принимающего секреты, нет.

### Альтернатива: Node.js long polling

Для этого режима требуется Node.js 22.13 или новее и исходящий HTTPS к `api.telegram.org` и домену сайта. Runtime runner использует встроенные модули Node.js; инструменты сборки Worker устанавливаются отдельно из `bot/package.json`. Сам сайт продолжает работать независимо.

Из корня проекта, когда переменные уже заданы средствами хоста:

```sh
npm run bot:start
```

Для локальной проверки с защищённым файлом переменных, например игнорируемым `.env.telegram`:

```sh
node --env-file=.env.telegram bot/runner.mjs
```

Подготовьте файл по образцу, ограничьте доступ к нему средствами ОС и заполните его самостоятельно. Не вводите реальные токены прямо в команду запуска. Не используйте общий компьютер или доступный другим пользователям файл.

На постоянном хосте настройте один фоновый процесс с этой командой, рабочей папкой проекта, секретами, постоянным `BOT_STATE_FILE`, автоматическим перезапуском после сбоя и наблюдением за его состоянием. Сервер должен оставаться включённым; закрытый терминал на личном компьютере не является постоянным размещением.

Runner проверяет `getMe` и отсутствие webhook, устанавливает меню, затем начинает polling. Сообщение о готовности процесса подтверждает старт polling, но не заменяет проверку bridge и привязки с сайтом.

### Подготовленные варианты размещения

Для собственного Linux-сервера есть [пример systemd unit](../bot/parimbank-bot.service.example) и пошаговый раздел в [bot/README.md](../bot/README.md). Перед установкой проверьте путь Node.js, выделенного пользователя, env-файл и unit именно на выбранном сервере. Локальная статическая проверка не означает установку сервиса.

Для Render сохранён [render.yaml](../render.yaml) как **платная альтернатива** с постоянным процессом и диском. Ранее Blueprint прошёл структурную проверку, но сервис не был развёрнут и оплачен. Он не применяется при выборе Workers Free. Не создавайте ресурсы Render для выполнения бесплатного варианта; перед отдельным применением оператор проверяет доступ и стоимость по [тарифам Render](https://render.com/pricing).

### Один экземпляр и webhook

На один токен допускается один polling-процесс. Локальный PID-lock рядом с checkpoint предотвращает второй запуск на том же диске, но не координирует разные серверы. Не запускайте одновременно старый и новый хост.

Если у бота уже настроен webhook, runner останавливается и не удаляет его автоматически. Оператор должен определить владельца прежней интеграции, остановить её и осознанно отключить webhook через Bot API перед переходом на polling. Telegram не поддерживает одновременную работу `getUpdates` и webhook. См. официальные [getUpdates](https://core.telegram.org/bots/api#getupdates), [deleteWebhook](https://core.telegram.org/bots/api#deletewebhook) и [FAQ](https://core.telegram.org/bots/faq#how-do-i-get-updates).

## 6. Привязка участником

1. Войдите на сайт под тем аккаунтом, чей баланс и билеты нужны в Telegram, и откройте `/telegram`.
2. Нажмите «Получить код подключения». Код действует **5 минут**. На сервере хранится его хеш, а не открытый код.
3. Откройте бота по кнопке «Открыть бота и передать код» либо отправьте `/link код` в личном чате с правильным ботом. Группы и сообщения от имени другого чата не подходят.
4. Вернитесь на сайт. При необходимости нажмите «Я отправил код — проверить».
5. Сверьте показанный числовой Telegram ID с аккаунтом, из которого вы отправили код. Username служит подписью и не заменяет ID. Нажмите «Да, подключить этот аккаунт» только для своего аккаунта.
6. Вернитесь в бот и откройте `/cabinet` или «Проверить привязку».

Одного предъявления кода боту недостаточно: без последнего подтверждения на сайте кабинет не открывается. Если указан чужой аккаунт или код истёк, создайте новый код. Никому не пересылайте код или одноразовую ссылку и не подтверждайте чужой ID.

Подтверждённая привязка действует **30 дней**, затем доступ нужно подтвердить заново через сайт. Это ограничение доступа, а не удаление баланса или билетов.

## 7. Команды и действия

| Команда | Результат |
| --- | --- |
| `/start`, `/cabinet` | Инструкция по привязке либо сводка аккаунта |
| `/balance` | Общий баланс и последние операции |
| `/tickets` | Собственные билеты, с переключением страниц |
| `/events` | Каталог, карточки и получение билетов |
| `/results` | Завершённые неархивные розыгрыши и победившие номера |
| `/coins` | Выбор 500, 1 000 или 2 000 монет и кнопка подтверждения запроса |
| `/coins 1000 Причина запроса` | Сразу отправить запрос собственной суммы и пояснение |
| `/notifications` | Просмотреть уведомления общего аккаунта |
| `/unlink` | Открыть управление привязкой на сайте; сама команда не отключает доступ |
| `/help` | Справка |

Для своей суммы разрешено от 1 до 100 000 монет, текст пояснения — от 3 до 1 000 символов. Запрос не начисляет монеты автоматически: его рассматривает администрация сайта. Повторная доставка того же Telegram-update или нажатие того же подтверждения не создают новый запрос. Новая команда от пользователя — отдельный запрос, поэтому при потере ответа сначала проверьте состояние.

В карточке розыгрыша выберите от 1 до 20 билетов. Бот показывает название, количество и общую стоимость; списание происходит только после «Подтвердить списание монет». Намерение действует **5 минут**. При подтверждении сервер заново проверяет доступ, привязку, состояние события, цену, свободные билеты и баланс. Подготовка не резервирует билеты. Повтор той же кнопки не списывает монеты второй раз.

«Отмена — в кабинет» возвращает в меню без покупки. Не нажимайте оставшуюся старую кнопку подтверждения, если передумали: срок её действия ограничен намерением. При сомнении откройте «Мои билеты» и баланс на сайте или в боте.

Бот показывает время по Екатеринбургу. Карточки текстовые: защищённое изображение R2 не передаётся Telegram, его можно посмотреть на сайте. Команда уведомлений читает сообщения аккаунта по запросу; автоматической рассылки о каждом событии нет. Переписка поддержки и согласование выдачи приза остаются в «Сообщениях» сайта.

Даже если ваш сайт-аккаунт имеет роль владельца или администратора, через бота доступны только пользовательские функции. Роли, настройки, начисление монет, управление чужими данными и административная переписка через bridge не предоставляются.

## 8. Отключение и отзыв доступа

На сайте откройте `/telegram` → «Отключить Telegram» и подтвердите. Баланс, билеты и история сохранятся. `/unlink` в боте ведёт на эту страницу, но до подтверждения на сайте связь остаётся активной. Отключение и блокировка аккаунта запрещают новые действия бота, в том числе ранее подготовленное, но ещё не исполненное получение билетов.

**Удаление приглашения Sites не отзывает D1-привязку автоматически.** При отзыве доступа оператор должен отдельно заблокировать аккаунт в приложении; пользователь может отключить свою привязку на сайте. 30-дневный срок ограничивает длительность связи, но не заменяет немедленный отзыв при необходимости. Сервисный токен процесса не получает сведения об актуальном составе аудитории для каждого Telegram-запроса.

Если Telegram-аккаунт скомпрометирован, зайдите на сайт через свой проверенный аккаунт и отключите связь; при отсутствии доступа обратитесь к администрации для блокировки аккаунта приложения. Пароль ChatGPT или коды входа боту не требуются.

## 9. Сбои, перезапуск и проверка

Для webhook Worker остановка, повтор доставки и диагностика описаны в [CLOUDFLARE_RU.md](../bot/CLOUDFLARE_RU.md). Следующие сведения о checkpoint и PID-lock относятся только к Node.js long polling.

Runner обрабатывает обновления последовательно и атомарно сохраняет offset после обработки каждого. При сети/5xx выполняется повтор с задержкой, при 429 учитывается `retry_after`. После обрыва возможно повторное текстовое сообщение; от повторных покупок и одинаковых запросов монет защищают серверные ключи.

SIGINT/SIGTERM останавливает polling, прерывает запросы и освобождает lock. После аварийного завершения проверьте, что старого процесса действительно нет, прежде чем удалять оставшийся `.lock`. Повреждённый checkpoint вызывает остановку: не сбрасывайте его вслепую. Ошибки авторизации, конфликт второго polling или webhook требуют устранить причину. Состояние баланса восстанавливается из D1 сайта, а не из offset-файла.

Изолированные тесты без настоящего токена:

```sh
npm run bot:check
```

После настройки оператор проверяет отдельным тестовым аккаунтом:

1. Код и подтверждение правильного ID, отказ до подтверждения и при просроченном коде.
2. Совпадение баланса и номеров билетов между сайтом и ботом, переходы страниц.
3. Получение билета в отдельном безопасном событии: сумму, результат, повтор той же кнопки без второго списания.
4. Запрос монет и повтор без дубля, отображение решения администрации.
5. Отключение/блокировку и отказ нового действия, повторную привязку через сайт.
6. Перезапуск процесса с сохранённым checkpoint и отсутствие второго экземпляра.

Тесты с подставными API не доказывают настоящий вход Telegram, сервисный доступ Sites или работу постоянного хоста. В этой поставке реальный запуск без предоставленных секретов и хоста не подтверждён.

| Проблема | Проверка |
| --- | --- |
| На сайте «Бот ещё не подключён» | Настройки username/bridge, публикация и готовность процесса |
| Бот не отвечает | Один работающий процесс, токен, сеть, отсутствие webhook и конфликтующего polling |
| Ошибка 401 от сайта | Сервисный токен Sites и совпадение bridge-секрета; не заменяйте их пользовательскими заголовками |
| Привязка ожидает подтверждения | Вернитесь на `/telegram` и подтвердите именно свой ID |
| Кнопка участия устарела | Обновите каталог и создайте новое намерение, предварительно проверив билеты и баланс |
| Доступ пропал через 30 дней | Повторите подтверждение через сайт |
| Не приходят сообщения о результатах сами | Откройте `/notifications`; автоматическая рассылка не включена |
| Конфликт lock | Проверьте живой процесс и его хост; не удаляйте lock работающего экземпляра |
