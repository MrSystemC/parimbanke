# Чек-лист запуска Telegram-кабинета

Используйте этот список перед объявлением бота рабочим. Наличие исходников и успешные изолированные тесты **не означают**, что бот подключён.

## 1. Создание бота

- [ ] Создан бот через @BotFather
- [ ] Получен токен (хранится только в секретах, не в Git и не в чате)
- [ ] Зафиксировано username бота (например `parimbank_bot`)

## 2. Настройка сайта

- [ ] Задан `TELEGRAM_BRIDGE_SECRET` (случайная строка ≥ 32 символов) как серверный секрет
- [ ] Задан `TELEGRAM_BOT_USERNAME` (без @)
- [ ] Сайт опубликован с этими секретами
- [ ] Страница `/telegram` доступна после входа

## 3. Размещение бота (выберите один вариант)

### Вариант A: Cloudflare Workers Free (рекомендуется)

- [ ] Выполнены шаги из `bot/CLOUDFLARE_RU.md`
- [ ] Worker опубликован
- [ ] Runtime secrets заданы (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BRIDGE_SECRET`, `SITE_URL` и др.)
- [ ] Webhook зарегистрирован
- [ ] `BOT_ENABLED=true`

### Вариант B: Node.js long polling (свой сервер)

- [ ] Следовать `bot/README.md` (systemd unit)
- [ ] Файл окружения заполнен, права 0600
- [ ] Процесс запущен и в статусе active
- [ ] Offset-файл на постоянном диске

## 4. Проверка end-to-end (тестовый аккаунт)

- [ ] Привязка: сайт → ссылка → бот → подтверждение Telegram ID на сайте
- [ ] Баланс в боте совпадает с сайтом
- [ ] Просмотр каталога и билетов
- [ ] Подготовка и подтверждение получения билетов (на тестовом розыгрыше)
- [ ] Запрос монет
- [ ] Отвязка
- [ ] Повторные сообщения не дублируют операции (идемпотентность)

## 5. Эксплуатация

- [ ] Назначен ответственный за мониторинг процесса/Worker
- [ ] Известно, как остановить и перезапустить бота
- [ ] Секреты хранятся безопасно и есть процедура ротации

После прохождения всех пунктов обновите `docs/RELEASE_READINESS_RU.md`.
