# Пар'ИМБА'нк

Клубные розыгрыши по городам: бесплатные игровые монеты, билеты, результаты, переписка с администрацией и панель управления. Новый экземпляр приложения запускается с пустым каталогом. Организатор создаёт розыгрыши, добавляет свои призы и отвечает за их передачу победителям.

## Быстрый локальный запуск

Требуются Node.js **22.13 или новее** и npm. Для полного набора проверок нужен также Python 3. В чистой копии репозитория автоматически используется переносимый режим для Windows, macOS и Linux.

```sh
npm run install:ci
node -e "const fs=require('node:fs');fs.copyFileSync('config/env.example','.dev.vars',fs.constants.COPYFILE_EXCL)"
npm run build
npm run db:migrate:local
npm run dev
```

Откройте адрес, напечатанный сервером, обычно `http://localhost:5173`. Для локального входа откройте `/signin-with-chatgpt?return_to=/admin`: переносимый dev-сервер использует фиксированный локальный аккаунт `seedy@sites.test`. Это средство разработки, а не производственная авторизация. Подробности, в том числе восстановление старой локальной базы без журнала миграций, приведены в [инструкции установки](docs/INSTALL_RU.md).

Создайте первый розыгрыш в панели. Каталог, билеты и участники не заполняются вымышленными данными. Монеты начисляются администратором бесплатно; покупка, вывод и перевод монет не предусмотрены.

## Основные команды

| Команда | Назначение |
| --- | --- |
| `npm run install:ci` | Установить зависимости по `package-lock.json` |
| `npm run dev` | Запустить разработку с обновлением интерфейса |
| `npm run typecheck` | Проверить TypeScript |
| `npm test` | Выполнить серверные и SQL-тесты; требуется Python 3 |
| `npm run check` | Проверить TypeScript и выполнить тесты |
| `npm run build` | Собрать Worker и клиент |
| `npm run db:migrate:local` | Применить недостающие миграции к локальной D1 |
| `npm start` | Запустить собранный Worker локально, без имитации входа |
| `npm run db:generate` | Сгенерировать новую SQL-миграцию после изменения схемы |
| `npm run bot:start` | Запустить альтернативный Node.js long polling с заранее заданными секретами |
| `npm run bot:check` | Изолированные проверки бота без настоящего токена |

`db:migrate:local` работает только с локальной БД и учитывает журнал уже выполненных миграций. Эта команда не обновляет опубликованный сайт. Проверки GitHub Actions также ничего не публикуют.

## Что находится в проекте

Интерфейс использует React и Vinext/Vite с файловой структурой App Router. Сервер работает как Cloudflare Worker. D1 хранит пользователей, события, билеты, баланс, переписку и журнал действий. R2 хранит загруженные изображения призов. Схема описана в `db/schema.ts`, последовательные миграции находятся в `drizzle/`.

В панели доступны роли владельца, администратора и модератора, создание и изменение розыгрышей, пауза и отмена с возвратом монет, запросы и корректировки баланса, блокировка аккаунтов, настройки механизмов, сообщения с внутренними заметками, журнал и CSV-экспорт. Владелец и администратор имеют одинаковые полномочия внутри приложения, включая настройки, назначение ролей и управление другими администраторами. Роль и статус настоящего владельца, а также собственные роль и статус защищены от изменений через панель. Команда может добавлять собственные категории каталога. Назначение победителя происходит на сервере после последнего билета; ручной замены результата нет.

## Telegram-кабинет

В репозитории предусмотрен Telegram-кабинет с общим балансом сайта, билетами, каталогом, подтверждением участия, запросами монет, результатами и просмотром уведомлений. Основной вариант размещения — отдельный webhook Worker на Cloudflare Workers Free; Node.js long polling сохранён как альтернатива. Это чат-бот, а не Mini App; административные команды и автоматическая доставка призов в нём отсутствуют. Привязка начинается на `/telegram` после входа на сайт и завершается подтверждением Telegram ID на сайте.

Для бесплатного варианта следуйте [CLOUDFLARE_RU.md](bot/CLOUDFLARE_RU.md): публикация папки `bot/`, runtime secrets и регистрация webhook. Free имеет квоты; постоянный платный процесс и диск не требуются. Реальный токен BotFather ещё не предоставлен, публикация и работа бота не подтверждены. Закрытую аудиторию Sites расширять не требуется. Команды и привязка участника — в [TELEGRAM_RU.md](docs/TELEGRAM_RU.md).

## Размещение и готовность к работе

В Sites проверенную личность посетителя передаёт платформа. Владелец задаётся серверным секретом `APP_OWNER_EMAIL`; первоначальные приглашённые администраторы — `APP_ADMIN_EMAILS`. Само приложение не содержит отдельного пароля администратора. Доступ к закрытому сайту и роль внутри приложения настраиваются отдельно. Назначение администратора не передаёт владение Sites, репозиторием GitHub или облачной инфраструктурой.

**Копия репозитория сама по себе не является безопасным самостоятельным публичным размещением.** Вне Sites сначала нужен доверенный шлюз авторизации либо адаптер проверенной серверной сессии, который исключает подмену личности и обход шлюза. Также необходимо подключить D1 и R2, применить миграции и настроить серверные секреты. [Инструкция установки](docs/INSTALL_RU.md) разделяет эти варианты.

Перед рабочим запуском организатор заполняет реальные условия розыгрышей, подтверждает наличие призов и порядок их передачи, назначает ответственных за поддержку, резервное копирование и мониторинг. В проекте нет платёжного провайдера, автоматической доставки призов, email/SMS/push-рассылки или независимого сервиса доказательства случайности. Эти возможности не заявляются как подключённые.

## Исходники и локальные данные

Храните в репозитории исходники, `package-lock.json`, миграции и `.openai/hosting.json`. Не публикуйте `.dev.vars`, `.env*`, локальные базы, содержимое `.wrangler/`, `.sites-runtime/`, `node_modules/` или секреты. Пример безопасной конфигурации находится в `config/env.example`.

Существующие данные не удаляются для очистки каталога: все прежние события с признаком `is_demo=1` архивируются, а пять известных стартовых событий без реальных покупок скрываются. История настоящих участий сохраняется для проверки администрацией. Это не заменяет резервное копирование перед обновлением.
