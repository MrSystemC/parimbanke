# Telegram-кабинет «Пар'ИМБА'нк»

Основной бесплатный вариант — **Cloudflare Workers Free с webhook**. Пошаговая публикация из GitHub, секреты и включение описаны в [CLOUDFLARE_RU.md](CLOUDFLARE_RU.md). Он не требует постоянно работающего Node.js-процесса или диска для offset. Приватный сайт Sites остаётся отдельным. Реальный deploy и подключение токена пока не подтверждены.

Ниже описана альтернатива — **Node.js long polling** для собственного Linux-сервера. Подготовленный Render Blueprint остаётся платным вариантом и этой инструкцией не применяется. Одновременно webhook и polling для одного бота не используются.

## Режим Node.js long polling

Этот процесс обслуживает личные чаты Telegram: общий с сайтом баланс и операции, билеты, каталог и результаты розыгрышей, получение 1–20 билетов с отдельным подтверждением и запросы бесплатных игровых монет. Административные действия через бота не предоставляются. Это кабинет с кнопками и командами, а не отдельное веб-приложение Telegram Mini App.

Для работы нужны Node.js 22.13+ и постоянный процесс на сервере с исходящим HTTPS к `api.telegram.org` и домену сайта. Новые npm-зависимости не требуются. Бот получает обновления через `getUpdates`; входящий публичный webhook ему не нужен. Запускайте ровно один экземпляр на токен и не включайте одновременно webhook другого приложения.

## Настройка

1. Создайте бота через официальный `@BotFather` в Telegram и получите токен. Храните его в защищённых переменных окружения, не в Git, переписке или командах с открытыми аргументами.
2. На стороне сайта задайте `TELEGRAM_BRIDGE_SECRET` (случайный секрет не короче 32 символов) и имя бота согласно основной инструкции интеграции. Опубликуйте настроенную версию сайта. Сайт должен сохранить текущую аудиторию: ради бота не нужно открывать его всем.
3. Задайте процессу значения из `env.example`. Для подготовки оставьте `BOT_ENABLED=false`: процесс будет ждать перезапуска, не запрашивая секретов и не обращаясь к Telegram или сайту. `SITES_SERVICE_TOKEN` — служебный доступ именно к этому сайту; `TELEGRAM_BRIDGE_SECRET` должен совпадать с серверной настройкой сайта. Не передавайте служебный токен в бот-командах или URL.
4. `SITE_URL` содержит только HTTPS-origin сайта, без пути, query и логина. `BOT_STATE_FILE` указывает на доступный процессу файл на постоянном диске. Каталог создаётся с ограниченными правами, файл хранит только offset обновлений.
5. Укажите `TELEGRAM_BOT_USERNAME` ожидаемого бота, например `parimbank_bot`. Начальный `@` допустим. При запуске токен сверяется с этим именем через `getMe` без учёта регистра; при несовпадении процесс останавливается до чтения webhook и изменения меню команд. Имя бота на сайте должно указывать на ту же интеграцию. Само заполнение ожидаемого имени не доказывает владение ботом.
6. После заполнения и проверки настроек измените `BOT_ENABLED` на `true` и перезапустите процесс. Запуск из корня проекта: `node bot/runner.mjs`. Для локального запуска с подготовленным закрытым файлом переменных Node.js поддерживает `node --env-file=/абсолютный/путь/к/закрытому-файлу bot/runner.mjs`. Не добавляйте этот файл в репозиторий.

`BOT_ENABLED` принимает только `true` или `false`. Отсутствующий ключ сохраняет прежний режим автоматического запуска; для нового развёртывания задавайте его явно. `TELEGRAM_BOT_USERNAME` необязателен для совместимости старых конфигураций, но в рабочем развёртывании его нужно заполнить, чтобы токен другого бота не изменил чужое меню. Когда процесс приостановлен, значения остальных настроек не читаются, offset-файл и lock не создаются. Изменение настройки требует перезапуска; `BOT_ENABLED=false` не является автоматической проверкой токена или связи с сайтом.

Runner сначала проверяет личность бота и существующий webhook, затем устанавливает меню команд. Если webhook уже настроен, запуск останавливается с объяснением; автоматически удалять чужую интеграцию он не будет. Отдельный PID-lock возле offset-файла предотвращает запуск двух локальных экземпляров. После аварийного завершения перед удалением оставшегося `.lock` убедитесь, что старый процесс остановлен. Не размещайте один токен на нескольких независимых дисках — Telegram вернёт конфликт polling.

## Постоянный процесс на Linux с systemd

Пример [parimbank-bot.service.example](parimbank-bot.service.example) предназначен для выбранного вами Linux-сервера с systemd. Он не устанавливается и не запускается вместе с сайтом автоматически. Пути ниже — схема размещения; перед установкой проверьте дистрибутив, путь к Node.js и наличие нужной версии. Команда `/usr/bin/node --version` должна показать Node.js 22.13 или новее. Если исполняемый файл расположен в другом месте, измените `ExecStart` в копии unit-файла.

1. Создайте отдельные системные пользователя и группу `parimbank-bot` без интерактивного входа. Например, на Debian/Ubuntu:

   ```bash
   sudo useradd --system --user-group --no-create-home --home-dir /nonexistent --shell /usr/sbin/nologin parimbank-bot
   ```

   Если такой пользователь уже есть, проверьте его назначение вместо повторного создания. Для другого дистрибутива используйте его команду создания системного пользователя и фактический путь к `nologin`.

2. Разместите проверенные `bot/client.mjs`, `bot/handler.mjs` и `bot/runner.mjs` в `/opt/parimbank/bot/`. Каталоги и код должны принадлежать администратору сервера и быть доступны пользователю `parimbank-bot` только для чтения и запуска Node.js. Для этого процесса установка npm-пакетов и запись в каталог кода не нужны.
3. Подготовьте `/etc/parimbank-bot.env`: сначала скопируйте `bot/env.example` с незаполненными секретами, владельцем `root:root` и правами `0600`, затем заполните его через защищённый редактор, например `sudoedit`. Не вставляйте токен в команды shell, unit-файл или Git. Значения `TELEGRAM_BOT_TOKEN`, `SITE_URL`, `SITES_SERVICE_TOKEN`, `TELEGRAM_BRIDGE_SECRET` берутся из вашей подтверждённой конфигурации; `TELEGRAM_BOT_USERNAME` задаёт ожидаемое имя бота. Для этого примера оставьте `BOT_STATE_FILE=/var/lib/parimbank-bot/offset.json`. Сначала используйте `BOT_ENABLED=false`, а после проверки конфигурации и готовности запуска переключите на `true` и перезапустите сервис.
4. Просмотрите unit-файл и скопируйте его в `/etc/systemd/system/parimbank-bot.service`. В нём указан только путь к env-файлу; реальные секреты там не хранятся. `StateDirectory` создаёт `/var/lib/parimbank-bot/` с правами `0700` для пользователя сервиса; этот каталог должен сохраняться при обновлении кода. Не копируйте его в репозиторий и не запускайте параллельно второй экземпляр.
5. После проверки заполненной конфигурации на выбранном сервере выполните:

   ```bash
   sudo systemd-analyze verify /etc/systemd/system/parimbank-bot.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now parimbank-bot.service
   sudo systemctl status parimbank-bot.service --no-pager
   ```

   Проверка unit-файла подтверждает его синтаксис и доступность настроенных исполняемых файлов, но не проверяет правильность токена, владение Telegram-ботом, служебный доступ к сайту или реальную привязку аккаунта. Состояние `active` тоже само по себе не подтверждает готовность кабинета: проверьте обезличенные сообщения запуска и затем свой тестовый аккаунт.

Для просмотра статусов процесса используйте `sudo journalctl -u parimbank-bot.service -n 50 --no-pager`. Для остановки — `sudo systemctl stop parimbank-bot.service`: systemd передаст SIGTERM, runner прервёт polling и освободит lock. Обычный перезапуск выполняется командой `sudo systemctl restart parimbank-bot.service`; при обновлении заменяйте только код после остановки процесса, сохраняя env-файл и каталог состояния. После аварийного завершения сначала убедитесь, что старый процесс отсутствует, и лишь затем разбирайте оставшийся lock-файл.

Unit ограничивает запись каталогом состояния и использует отдельного пользователя. В нём намеренно нет `MemoryDenyWriteExecute`: этот запрет может нарушить работу JIT в Node.js. Настройки безопасности сервера и сетевой доступ проверяет его оператор; пример не означает, что сервер уже выбран, настроен или оплачен.

## Привязка аккаунта

Пользователь входит на сайт под своим аккаунтом и открывает `/telegram`, получает одноразовую ссылку, затем запускает бота по ней. После этого нужно вернуться на сайт и явно подтвердить показанный Telegram-аккаунт. Только после подтверждения бот читает кабинет. Имя пользователя служит подписью; связь хранится по числовому Telegram ID. Отвязка подтверждается владельцем аккаунта на сайте. Не пересылайте одноразовые ссылки другим людям.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/cabinet` | Привязка или сводка кабинета |
| `/balance` | Баланс и последние операции |
| `/tickets` | Все собственные билеты, страницы по 10 |
| `/events` | Каталог, карточка приза и выбор количества 1–20 |
| `/results` | Завершённые неархивные розыгрыши |
| `/coins` | Выбор суммы и подтверждение запроса монет |
| `/coins 1000 Причина запроса` | Запрос своей суммы с сообщением |
| `/notifications` | Уведомления из общего аккаунта |
| `/unlink` | Ссылка на управление привязкой на сайте |
| `/help` | Справка |

Кнопка количества билетов только подготавливает серверное намерение. Списание происходит после отдельного нажатия «Подтвердить списание монет». Повтор одного намерения использует тот же серверный ключ и не оплачивает билеты повторно. Свойства приза и доступность проверяет сайт при подтверждении. Запросы монет также передают устойчивый ключ, чтобы повторная доставка Telegram-update не дублировала запрос.

Все даты бот показывает по Екатеринбургу. Тексты отправляются без HTML/Markdown-разметки, поэтому содержимое названия не обрабатывается как HTML/Markdown-команды. Telegram может автоматически распознать адрес в обычном тексте; предпросмотр ссылок отключён. Изображение из закрытого R2 не передаётся Telegram по защищённому URL; карточка бота показывает текст, а иллюстрация доступна на сайте.

## Эксплуатация и проверки

Проверка без настоящего токена: `node bot/test-bot.mjs`. Тесты используют подставные API и не связываются с Telegram. Для запуска в рабочей среде дополнительно проверьте свой тестовый аккаунт: привязку с подтверждением на сайте, одинаковый баланс, все страницы билетов, подготовку и отмену намерения, повтор подтверждения в отдельном безопасном тестовом розыгрыше и отвязку. Рабочие розыгрыши и реальные балансы не используйте для разрушительных испытаний.

SIGINT/SIGTERM прерывает polling и HTTP-запросы, освобождает lock и завершает процесс. Offset сохраняется атомарно после обработки каждого update. При сетевой ошибке или ответе 5xx обновление повторяется; при 429 учитывается `retry_after`. Возможна повторная отправка ответа после обрыва сети, но повторное изменение билетов и запросов предотвращается серверными ключами. Недоступный пользователю чат (400/403 Telegram) пропускается, чтобы не остановить остальные чаты. Ошибки авторизации и конфликт polling останавливают процесс; перезапускайте его после исправления причины.

Не выводите секреты и содержимое личных кабинетов в логи. Runner пишет только обезличенные статусы. Контролируйте состояние процесса и резервируйте постоянный offset-файл; восстановление самого аккаунта и данных выполняется на стороне сайта.

Основание протокола: официальные [Bot API](https://core.telegram.org/bots/api), [Bot Features — Deep Linking](https://core.telegram.org/bots/features#deep-linking) и [FAQ — Getting Updates](https://core.telegram.org/bots/faq#how-do-i-get-updates). Наличие исходников и прохождение изолированных тестов не означают, что бот уже зарегистрирован, подключён к токену или запущен на постоянном сервере.
