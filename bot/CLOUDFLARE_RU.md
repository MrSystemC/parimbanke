# Telegram-бот на Cloudflare Workers Free

Это основной вариант бесплатного размещения Telegram-транспорта. Отдельный Worker принимает webhook Telegram и обращается к защищённому bridge существующего сайта. Постоянный Node.js-сервер, платный background worker и диск для offset ему не нужны. Основной сайт, его D1/R2 и закрытая аудитория Sites остаются на прежнем месте.

**Публикация и подключение пока не подтверждены.** Код и инструкции не означают успешный вход в Cloudflare, созданный Worker или работающий бот. Настоящий токен BotFather не предоставлялся. Выполнять шаги с секретами и активацией нужно в своём аккаунте.

## 1. Что означает бесплатный вариант

На 9 ноября 2026 года Workers Free включает **100 000 входящих запросов в сутки** и **10 мс CPU на вызов**. Ожидание сетевого `fetch` не учитывается как CPU. Cloudflare предлагает начало работы без банковской карты. Это ограниченный бесплатный тариф, а не обещание неограниченной нагрузки или бесплатности всех сторонних сервисов: [тариф Workers](https://developers.cloudflare.com/workers/platform/pricing/), [ограничения](https://developers.cloudflare.com/workers/platform/limits/), [Cloudflare Free](https://www.cloudflare.com/).

Выберите именно Free и не подключайте платные ресурсы для выполнения этой инструкции. Worker бота не требует собственной D1, R2, KV или платного диска: состояние аккаунта хранится на сайте. Расходы и квоты существующего сайта обслуживаются отдельно. После запуска проверьте реальные CPU time и ошибки в Cloudflare: прохождение локальных тестов не доказывает, что любой размер каталога уложится в бесплатный лимит.

## 2. Что подготовить

- Аккаунт Cloudflare с доступом к Workers Free.
- Доступ Cloudflare Git-интеграции к репозиторию с актуальной папкой `bot/`.
- Свой бот BotFather и его ожидаемый username. В `wrangler.jsonc` сейчас указан `parimbank_bot`; проверьте, что это именно ваш бот.
- Работающий сайт с `/telegram` и `/api/telegram/bridge`, правильным `TELEGRAM_BOT_USERNAME` и отдельным `TELEGRAM_BRIDGE_SECRET`.
- Сервисный доступ Sites к этому сайту. Он не заменяется Git-токеном или ролью администратора приложения.

Создание бота и привязка участника описаны в [основном руководстве Telegram](../docs/TELEGRAM_RU.md). Токен не нужно присылать в чат или записывать в GitHub: он вводится в защищённой конфигурации хоста.

## 3. Создание Worker из GitHub

1. В [Cloudflare Dashboard](https://dash.cloudflare.com/) откройте **Workers & Pages → Create application** и выберите GitHub.
2. Авторизуйте нужный GitHub-аккаунт и разрешите доступ к выбранному репозиторию. Доступ ChatGPT к GitHub не является доступом Git-интеграции Cloudflare.
3. Выберите репозиторий и ветку, которую действительно хотите публиковать. Для основной ветки обычно используется `main`.
4. Укажите настройки из таблицы. Root directory особенно важен: корень всего репозитория собирает сайт, а здесь нужен только транспорт бота.

| Поле Cloudflare | Значение |
| --- | --- |
| Worker name | `parimbank-telegram-webhook`, как `name` в `bot/wrangler.jsonc` |
| Root directory | `bot` |
| Build command | `npm test && npm run build` |
| Deploy command | `npm run deploy` |
| Node.js для сборки | 22.13 или новее |
| Production branch | Ваша проверенная ветка, обычно `main` |

Если меняете имя Worker, согласуйте его с `name` в конфигурации до публикации. Внешний каталог `bot/` содержит собственный `package.json`: команда `npm start` там запускает long polling и не нужна в Workers Builds. Команда `npm run build` выполняет только проверочную сборку Wrangler с `--dry-run` в `dist-worker`; публикацию выполняет именно `npm run deploy`.

Не передавайте рабочие токены в build variables: для сборки они не нужны. Они задаются как runtime secrets уже созданного Worker. На этом этапе можно выполнить **Save and Deploy** без секретов: по умолчанию обработка бота выключена. При необходимости отключите preview builds для других веток либо сохраняйте их без рабочих секретов и с выключенным ботом. Webhook должен указывать только на основной стабильный адрес.

Официальная справка: [подключение репозитория](https://developers.cloudflare.com/workers/ci-cd/builds/), [поля сборки и root directory](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).

## 4. Проверка выключенного Worker

После успешной публикации Cloudflare выдаст HTTPS-адрес вида `https://parimbank-telegram-webhook.<ваш-поддомен>.workers.dev`. Пользуйтесь фактическим адресом панели.

Откройте `/health`. До активации ожидается:

```json
{"ok":true,"enabled":false}
```

Это подтверждает доступность маршрута. Проверка `/health` не обращается к Telegram или Sites и не проверяет токен. `/webhook` принимает только POST; открытие его в браузере не является тестом бота. Отсутствующий `BOT_ENABLED` в Worker означает `false`; выключенный webhook отвечает 503, не выполняя действий.

## 5. Runtime secrets и настройки

Откройте созданный Worker → **Settings → Variables and Secrets → Add**. Для чувствительных значений выбирайте **Secret**. После ввода примените изменения через **Deploy**. Это настройки исполнения Worker, а не секреты этапа сборки. Официальная инструкция: [секреты Workers](https://developers.cloudflare.com/workers/configuration/secrets/).

| Имя | Значение и хранение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Secret: настоящий токен BotFather |
| `SITES_SERVICE_TOKEN` | Secret: сервисный bearer для доступа к нужному сайту Sites |
| `TELEGRAM_BRIDGE_SECRET` | Secret: точно такой же секрет 32–256 символов, как на основном сайте |
| `TELEGRAM_WEBHOOK_SECRET` | Secret: отдельная случайная строка из 32–256 символов `A–Z`, `a–z`, `0–9`, `_`, `-` |
| `BOT_ENABLED` | Secret: сначала `false`, затем явно `true` после подготовки |
| `TELEGRAM_BOT_USERNAME` | Ожидаемый username из `wrangler.jsonc`; должен совпадать с токеном и настройкой сайта |
| `SITE_URL` | HTTPS-origin существующего сайта из `wrangler.jsonc`, без дополнительных путей и параметров |

`TELEGRAM_WEBHOOK_SECRET` защищает входящий запрос Telegram. `TELEGRAM_BRIDGE_SECRET` защищает обращение Worker к сайту. Они должны быть разными. Токен BotFather не заменяет ни один из них. Сгенерируйте секрет в менеджере паролей или другом доверенном локальном средстве; не используйте пример из документации как готовый секрет.

`BOT_ENABLED` намеренно отсутствует в `vars` файла Wrangler: активация задаётся отдельно в защищённой конфигурации, не включается обычным коммитом и не сбрасывается копированием исходных переменных. Не добавляйте секреты в `vars`, `render.yaml` или build command. После изменения `SITE_URL`/username согласуйте источник конфигурации и повторите публикацию, чтобы следующий deploy не вернул старые значения.

На стороне Sites нужен тот же `TELEGRAM_BRIDGE_SECRET` и username. Токен Telegram и webhook-secret туда добавлять не требуется. Аудиторию сайта оставьте прежней: внешний адрес доступен только у транспорта, а его `/webhook` проверяет `X-Telegram-Bot-Api-Secret-Token`.

## 6. Настройка webhook и активация

Настройка выполняется отдельным операторским CLI из репозитория. Публичного адреса `/setup` или кнопки, принимающей токен в браузере, у Worker нет. Перед переключением остановите прежний long-polling процесс: один бот не должен одновременно обслуживаться разными транспортами.

После регистрации webhook Telegram будет отправлять обновления на `https://<фактический-Worker>/webhook` с отдельным секретным заголовком. Адрес не содержит токен. Используйте только основной HTTPS-адрес своего Worker, а не preview ветки и не адрес закрытого сайта.

На своём доверенном компьютере с Node.js 22.13+ подготовьте закрытый файл, например игнорируемый `.env.telegram-webhook` в корне проекта. Заполняйте его через редактор с ограниченным доступом, не через команды с токеном в аргументах:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_BOT_USERNAME=parimbank_bot
TELEGRAM_WEBHOOK_SECRET=
TELEGRAM_WEBHOOK_URL=https://your-worker.your-subdomain.workers.dev/webhook
```

Замените username и URL фактическими значениями. Секрет webhook должен совпадать с runtime secret Worker. Сервисный токен Sites и секрет bridge этому CLI не нужны: они уже хранятся на Worker.

Из корня проекта сначала выполните просмотр без изменений:

```sh
node --env-file=.env.telegram-webhook bot/configure-webhook.mjs
```

Без флага `--confirm` скрипт вызывает только `getMe` и `getWebhookInfo`, проверяет ожидаемый username и показывает безопасную сводку. Он не регистрирует webhook и не меняет команды. Если токен принадлежит другому боту, исправьте настройки. Этот просмотр не проверяет секреты Sites или доступность Worker.

После проверки установите runtime secret `BOT_ENABLED=true` в Cloudflare и примените через Deploy. `/health` должен показывать `enabled:true`. Затем явно зарегистрируйте webhook:

```sh
node --env-file=.env.telegram-webhook bot/configure-webhook.mjs --confirm
```

Скрипт устанавливает фиксированное меню команд и webhook, затем проверяет `getWebhookInfo`. Он принимает только HTTPS-URL с путём ровно `/webhook`, без логина, параметров и фрагмента. Устанавливаются `max_connections=1`, типы обновлений `message` и `callback_query`; накопленные обновления сохраняются (`drop_pending_updates=false`).

Если обнаружен другой непустой webhook, обычный `--confirm` не должен заменять его. Проверьте, кому принадлежит прежняя интеграция, и остановите её. Только для осознанного переноса используйте оба флага:

```sh
node --env-file=.env.telegram-webhook bot/configure-webhook.mjs --confirm --replace-existing
```

Не запускайте эту команду для случайного токена или чужого бота. Токены не передаются в аргументах или URL скрипта и не выводятся в сводке. После настройки храните env-файл с теми же ограничениями доступа либо удалите локальную копию после переноса в свой менеджер секретов.

### Локальные проверки перед публикацией

Из папки `bot/` после установки зависимостей по её lockfile:

```sh
npm ci
npm test
npm run test:runtime
npm run build
```

Это изолированные проверки обработчиков и smoke-проверка Workers runtime, затем dry-run сборка. Они не отправляют настоящие сообщения, не настраивают webhook и не публикуют Worker. В Dashboard используется `npm test && npm run build`; runtime smoke можно выполнять отдельно перед передачей коммита. Не добавляйте настройку webhook в автоматическую build/deploy-команду.

## 7. Проверка реальной работы

Успешный deploy и `/health` с `enabled:true` не подтверждают токен или доступ к Sites. После настройки:

1. Проверьте ожидаемый username через операторский CLI и результат `getWebhookInfo`.
2. Откройте `/start` в личном чате своего бота.
3. Выполните привязку с сайта и подтвердите показанный числовой Telegram ID.
4. Сверьте баланс и билеты в боте и на сайте, откройте каталог и уведомления.
5. На отдельном безопасном тестовом событии проверьте подтверждение получения билетов и повтор той же кнопки без второго списания.
6. Отключите тестовую привязку на сайте и убедитесь, что новые действия бота запрещены.
7. Проверьте ошибки и CPU time в Cloudflare, включая страницы большого каталога.

Worker не хранит offset-файл. Telegram повторяет неуспешную доставку, а серверные ключи сайта защищают покупки и запросы монет от дублирования. Повтор текстового ответа после обрыва связи возможен. Обработка ограничена по времени; при временном отказе Worker возвращает ошибку для повторной доставки, а не сообщает об успешной обработке заранее.

## 8. Обновления и остановка

Публикуйте проверенные изменения через выбранную Git-ветку. Сохраняйте прежний основной адрес и runtime secrets. Не запускайте Node runner параллельно webhook. Для временной остановки задайте `BOT_ENABLED=false` и примените конфигурацию: это прекращает новые действия, но не удаляет привязки, баланс и билеты. Telegram может повторять накопленные обновления после включения; остановка не является очисткой очереди.

При смене webhook-secret обновите одинаковое значение в Worker и конфигурации Telegram. При раскрытии токена отзовите его в BotFather и заново настройте оба конца интеграции. Не печатайте токены, тела личных кабинетов и секретные заголовки в логах. Встроенные сообщения транспорта содержат только общие статусы.

| Проблема | Что проверить |
| --- | --- |
| Сборка ищет файлы сайта | Root directory должен быть `bot` |
| Имя Worker не совпадает | Имя панели должно соответствовать `name` в Wrangler |
| `/health` показывает `false` | `BOT_ENABLED` ещё не включён или изменение не опубликовано |
| `/health` успешен, бот молчит | Токен/username, runtime secrets, webhook и доступ к bridge; health этого не проверяет |
| 401 на `/webhook` | Совпадение webhook-secret и заголовка Telegram |
| 503 на `/webhook` | Бот выключен, отсутствует конфигурация, неверна личность бота либо временно недоступен Telegram/Sites |
| Конфликт обновлений | Остановите старый polling и проверьте фактический webhook |
| Превышение Free-лимитов | Проверьте запросы и CPU; бесплатный тариф не безлимитен |

## 9. Альтернативы

Long polling на собственном Linux-сервере остаётся в [bot/README.md](README.md). Подготовленный [Render Blueprint](../render.yaml) — отдельный **платный** вариант, который не применяется этой инструкцией. Его наличие не означает созданный или оплаченный сервис. Для запроса бесплатного размещения сначала используется Workers Free; сам основной сайт от этого не переносится.
